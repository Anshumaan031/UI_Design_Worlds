# Design Worlds

A gallery of live UI "worlds". Each design is a self-contained folder that can be lifted into another project. `index.html` is only a shell. It works from `file://`, with no server.

## Layout

- `designs/<id>/` one design: `design.json`, `sample.html`, `sample.css`, optional `sample.js` and `spec.md`
- `designs/_template/` the starting point (folders starting with `_` are skipped by the build)
- `app/` the gallery (search, filters, detail view). Not design content.
- `data/` and `designs/*/DESIGN.md` are generated. Never edit them by hand.
- `scripts/` `new.mjs` (scaffold), `build.mjs` (generate), `lib.mjs` (shared)

## Adding a design

1. `node scripts/new.mjs <id> "Name" <prefix>` (the prefix is 2-3 letters, e.g. `mw`)
2. Fill in the four files in `designs/<id>/`
3. `node scripts/build.mjs` (it validates and writes `data/` and `DESIGN.md`)
4. Open `index.html#/d/<id>` and check the browser console is clean

If a design is generated by another tool (e.g. impeccable), put its output into this folder structure. Don't leave it at the project root, and don't overwrite a root-level `DESIGN.md`.

## Rules for a design

- Every class in `sample.html` and `sample.css` uses the design's unique prefix (`mw-card`), and every CSS rule is scoped under it. Samples are injected into the gallery page, so unscoped selectors leak into the app and into other designs.
- No `body`, `html` or `:root` selectors in `sample.css`. Put tokens on the root element of the sample.
- `sample.js` is not a module. It runs as a function body with `root`, `$`, `$$`, `reduced`, `setInterval`, `setTimeout` and `requestAnimationFrame` in scope. No `import`, no `document.querySelector` outside `root`, no leaking globals. Respect `reduced` (prefers-reduced-motion).
- Fonts go in `design.json` `fonts` as Google Fonts family specs (e.g. `"Fraunces:wght@400;700"`). The gallery loads them only when the design opens.
- Required `design.json` fields: `name tone play status fit idea palette`. The build fails without them.
  - `tone`: `light` or `dark`. `play`: `low`, `medium` or `high`. `status`: `built` or `proposed`.
  - `palette`: `[{ name, hex, role }]`. For a gradient add `css` as well.
- `use` and `feel` are the search facets. Reuse existing tags from other `design.json` files before inventing new ones, or the filters fragment. `keywords` is free text for search.
- Colour families are derived from `palette` automatically. Keep the palette honest.
- Keep the sample useful on its own: a real mini-screen, not a swatch page.

## Gallery chrome vs designs

The gallery chrome (`app/app.css`, `index.html`) is deliberately neutral so the designs stand out. Don't copy chrome styles into a design, and don't restyle the chrome to match one design.

## Verifying

There is no test suite. After a build, load the design in headless Chrome or a browser, confirm there are no console errors, and look at it at about 500px wide as well as desktop width.
